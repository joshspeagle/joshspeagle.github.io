# Content Update Checklist

When the user asks to "update the website", walk through each category below and ask what (if anything) has changed. All edits go in `assets/data/content.json` unless noted. After edits, **bump `site.lastUpdated` in `content.json` to today** (it is the date every content-driven page's footer and `sitemap.xml` entry shows — the build never reads the clock), then run `npm run build` and `npm run check`.

> **`pages.*` holds every page's chrome copy.** `pages.<page>` (`kicker`/`title`/`tagline`) drives each secondary page's header band, its `<title>` and its generated meta/OG description; `pages.home` drives the hero (`kicker`/`title`/`nameZh`/`tagline`/`cta`) and the four Home section headings (`pages.home.sections.about|research|team|join`). `tagline` is emitted as raw HTML (so inline `<strong>` etc. work); `kicker`/`title` are escaped. Every `.html` file is build output — never edit one.

> **Declared, not derived, colours.** A new talks category, service category, teaching department or news type must declare an `accent` (the CSS colour class) in `content.json`; otherwise the build prints a WARNING and the card gets a neutral stripe. The ADS library ids behind the Publications dashboard live in `sections.publications.libraries`.

Update the "Last edited" column each time a category is modified.

For adding or editing mentees specifically (category 6/7), see the `adding-mentees` skill.
