Part 1 of 9 · Experimental method and setup

Tuning a network one question at a time

Josh Speagle Notes on the Playbook's section on a scientific approach to improving model performance ↗

Part of a series of notes on Google Research's Deep Learning Tuning Playbook. Read what the Playbook is and how these notes work.

You have a network that trains, and a validation score you would like to improve. The tempting next step is to change several things at once, or to hand every hyperparameter in the config to a search tool and launch a few dozen runs overnight. The Playbook argues for a slower loop. Ask one question per round of experiments, and design each round so its answer can be trusted. These are my notes on how the loop works, from scoring a single run to spending a fixed budget of runs.

One question per round

Suppose validation accuracy has stalled a few points short of where you need it. There is no shortage of ideas. You could switch optimizers, add dropout, add a learning-rate decay schedule and make the network deeper. If you try all four in one run and the score improves by half a percent, you still do not know which change helped. One of them might account for the whole gain while another made the model worse and slowed training down.

The other tempting option is to put every hyperparameter into an automated search. The Playbook's authors consider this impractical, because the space of possible configurations is extremely large. In their words, there are not yet "any algorithms sophisticated enough to efficiently search this space without human guidance." Three values for each of twelve hyperparameters give $3^{12} = 531{,}441$ combinations, and a search of 50 or 100 runs covers almost none of them.

The Playbook's alternative is its incremental tuning strategy (the Playbook's section ↗). You start from a simple configuration that works and improve it in a sequence of rounds. Each round asks one narrow question. Inside a round you run a study, the Playbook's name for a set of training runs with different hyperparameter settings, and each run in the study is a trial. When the evidence says a change helps, you adopt it into your best configuration. The Playbook calls each such update a launch, whether or not anything ships to production.

The Playbook's summary · The incremental tuning strategy ↗

Start with a simple configuration and incrementally make improvements while building up insight into the problem. Make sure that any improvement is based on strong evidence to avoid adding unnecessary complexity.

Each round repeats the four steps in . The first step decides whether the rest can succeed. The Playbook asks for a goal narrow enough that the experiments can make progress on it, and its examples are trying one potential improvement (a new regularizer, a preprocessing choice), understanding the effect of one hyperparameter such as the activation function, and, late in a project, greedily lowering validation error (choosing the goal ↗).

The Playbook says that in practice most of the time goes to gaining insight into the problem, which it calls exploration, and comparatively little goes to greedily lowering validation error, or exploitation (exploration vs exploitation ↗). A round in which a new regularizer fails to help is still useful if the plots show you why. Insight is useful in later rounds. It tells you which hyperparameters the validation error is sensitive to, which ones interact and need re-tuning together, and which ones can be left alone in future rounds. Once the search space is understood, a final stage switches to exploitation, which the Playbook suggests running with Bayesian optimization (Part 6).

Every step of the loop compares training runs, so the first practical question is which single number should stand for a run.

Scoring one training run

Say you train for 20,000 steps with some hyperparameter configuration $\mathbf{h}$ (the learning rate, the weight decay and every other setting of the run). To compare this run with others you need one validation score for it, which the Playbook calls the trial's result. The simplest choice is the validation error at the last step, but the end of training is often not where the run did best.

  • The run may have peaked earlier. A run with a high learning rate or little regularization can reach its best validation error partway through and then get worse as it overfits the training set.
  • Validation measurements fluctuate. Once the validation curve levels off, each evaluation still moves up and down a little from one checkpoint to the next. A single reading at the last step can fall on a high point by chance.

The Playbook's recommendation is to run periodic evaluations at regular step intervals, keep the few best checkpoints seen so far on disk (a small buffer), and pick the best one when the run ends (saving checkpoints ↗). It calls this retrospective optimal checkpoint selection. Written out, the trial's result is the lowest validation error over the evaluation steps:

$$\hat{L}_{\text{trial}}(\mathbf{h}) \;=\; \min_{t \,\in\, \mathcal{T}_{\text{eval}}} L_{\text{val}}(\boldsymbol{\theta}_t).$$

Here $\boldsymbol{\theta}_t$ are the model's weights at step $t$, $L_{\text{val}}$ is the validation error, and $\mathcal{T}_{\text{eval}}$ is the set of steps at which you evaluate (every 1,000 steps in ). Every trial runs to its full step budget and the checkpoint is chosen afterwards, so you do not need an early-stopping rule that guesses during training when to quit. The Playbook says prospective early stopping is usually unnecessary for that reason.

In the run stopped improving around step 5,000, so the 0.0090 between the last checkpoint and the best one comes from evaluation noise. On a run that overfits, the gap would also include the damage done by the later steps.

Why the best checkpoint reads below the plateau

The toy's plateau is exactly 0.2, yet the selected checkpoint reads 0.1899. Taking the minimum of 20 noisy evaluations picks the one with the largest downward fluctuation, so on average the minimum sits below the true plateau. More evaluations give more chances for a low reading. Over 300 seeds of the toy, the median gap between the last and the selected checkpoint grows from 0.007 when evaluating every 2,500 steps to 0.011 when evaluating every 250 steps.

My own takeaway, which goes beyond the Playbook's text, is to evaluate every trial you compare on the same schedule, so that no trial gets more chances at a low reading than another. A number you report for the final model should come from a separate test set, since the selected checkpoint's validation error is biased low.

One trial gives one number. A round runs many trials, and the next question is how to look at them together.

Reading a set of runs

A study needs a few choices: which hyperparameters vary across trials, the range of values each may take (the search space), and how many trials to run. A search algorithm then picks each trial's settings within that space (creating a set of studies ↗). shows a study of 20 trials that varies the learning rate $\eta$ and the weight decay $\lambda$ together. Each trial trains for 20,000 steps and reports its best checkpoint, and the trial with the lowest result is the study's best trial.

A table sorted by score tells you which trial won. To check whether the search space was in the right place, the Playbook recommends a basic hyperparameter axis plot, which plots every trial's validation score against one hyperparameter, one point per trial (identifying bad search space boundaries ↗). The first thing to check on such a plot is where the best trials sit. If they crowd against one edge of the range, a better value may lie beyond it, and the Playbook's advice is to widen the search in that direction and run again.

Making a comparison fair

Take a concrete round. Your model has four hidden layers, and you want to know whether six would reduce validation error. The quickest experiment keeps everything from your current configuration, including the learning rate you tuned for four layers, changes the depth and runs once.

The Playbook points out that the best learning rate generally depends on the architecture. The value that suited four layers need not suit six. Running the six-layer model at the four-layer model's learning rate tests the new model at a setting tuned for the old one, and shows how that can mislead.

The fix is to search the learning rate separately for each depth and compare the best result each depth reaches. The Playbook builds its experimental design around this idea by giving every hyperparameter in a round one of three roles (identifying scientific, nuisance and fixed hyperparameters ↗):

  • Scientific hyperparameters are the ones whose effect you are trying to measure. In the example, the number of hidden layers.
  • Nuisance hyperparameters are the ones you tune separately for each value of the scientific hyperparameters, so that the comparison is fair. In the example, the learning rate. Their values do not matter for their own sake, and the name comes from the statistical idea of a nuisance parameter.
  • Fixed hyperparameters keep one value for the whole round. Fixing one saves trials and adds a caveat, because your conclusion may not hold at other values of that hyperparameter.

With these roles, the quantity a round compares is the best score each value of the scientific hyperparameter reaches once the nuisance hyperparameters are tuned:

$$L^\star(h_{\text{sci}}) \;=\; \min_{\mathbf{h}_{\text{nuis}}} \, L(h_{\text{sci}},\, \mathbf{h}_{\text{nuis}}).$$

Here $h_{\text{sci}}$ is one value of the scientific hyperparameter (six layers, say), $\mathbf{h}_{\text{nuis}}$ collects the nuisance hyperparameters, $L$ is the validation error a run reaches, and the minimum runs over the nuisance search space. The Playbook describes the same operation in words as "optimizing away" the nuisance hyperparameters. In practice the minimum is taken over the trials you ran, so it is an estimate, and its quality depends on how the trials are spent.

How much a fixed learning rate distorts the comparison

Suppose each option's validation error is a parabola in $x = \log_{10}\eta$ around its own best learning rate $x^\star(h_{\text{sci}})$, as in :

$$L(h_{\text{sci}}, x) = L^\star(h_{\text{sci}}) + c\,\big(x - x^\star(h_{\text{sci}})\big)^2.$$

At a fixed learning rate $x_0$, option A scores $L^\star(A) + c\,(x_0 - x^\star_A)^2$ and option B scores $L^\star(B) + c\,(x_0 - x^\star_B)^2$. The fixed comparison therefore adds a penalty to each option that grows with the square of its distance from $x_0$. Fixing $x_0$ at the old model's best learning rate gives the old model no penalty and the new model a penalty of $c\,(x^\star_A - x^\star_B)^2$. In the toy that penalty is $0.05 \times 0.8^2 = 0.032$, larger than the true advantage of $0.015$, which is why the ranking reverses.

Statisticians call the curve $L^\star(h_{\text{sci}})$, a minimum over the nuisance parameters at each value of the parameter of interest, a profile. The Playbook does not use the word, but its "optimizing away" is the same operation.

Which role does a hyperparameter take?

The Playbook stresses that a role is not a property of the hyperparameter. It changes with the goal of the round. The activation function, for instance, could be scientific in a round that compares ReLU and tanh, nuisance in a round that tunes it separately for each depth, and fixed in a round that tests something else on a ReLU network. The Playbook still gives rules of thumb for common kinds of hyperparameters:

  • Optimizer hyperparameters, such as the learning rate, momentum and Adam's $\beta$ parameters, are usually nuisance hyperparameters, because they tend to interact the most with other changes. They are rarely scientific, since the best learning rate for today's pipeline could change with the next change to it. The Playbook allows fixing some of them when resources are short or when there is strong evidence that they do not interact with the question.
  • The choice of optimizer is usually scientific, when comparing optimizers is the question, or fixed otherwise.
  • Regularization splits in two. Whether to use a technique such as dropout is scientific or fixed, and the strength it introduces, such as the dropout rate, is a nuisance hyperparameter. Once dropout is adopted, its rate stays a nuisance hyperparameter in later rounds.
  • Architecture choices such as the number of layers are usually scientific or fixed, because, as the Playbook notes, they tend to have large effects on training speed and memory use.

applies these rules to three goals, using the Playbook's own examples. Pick a goal and press a hyperparameter to read why it takes its role, or switch to "Test yourself" and assign the roles first.

The third goal in shows one more complication. Each optimizer brings its own settings. Nesterov momentum adds a momentum coefficient, and Adam adds $\beta_1$, $\beta_2$ and $\epsilon$. The Playbook calls hyperparameters that exist for some values of the scientific hyperparameters conditional hyperparameters. Both optimizers have a learning rate, but the Playbook warns against treating the two as one hyperparameter, because the ranges that work well for each typically differ by several orders of magnitude. Each optimizer's study gets its own learning-rate search.

Every nuisance hyperparameter you tune costs trials, and the number of trials in a round is set by your compute.

Spending a fixed budget of trials

The Playbook names three goals that a study design has to balance within a limited budget (striking a balance ↗):

  1. comparing enough different values of the scientific hyperparameters,
  2. tuning the nuisance hyperparameters over a large enough search space,
  3. sampling that search space densely enough.

Doing better on any of the three costs either more trials or some of another. To see the trade-off in numbers, suppose you can afford $K_{\text{total}} = 48$ trials and want to compare $M = 3$ values of a scientific hyperparameter, with one study per value. Each study gets $K$ trials, spread over a learning-rate range $W$ decades wide (a decade is a factor of 10, so the range from $10^{-4}$ to $10^{-1}$ is three decades). The number of trials per decade is

$$K = \frac{K_{\text{total}}}{M}, \qquad \rho = \frac{K}{W}.$$

With 16 trials over 3 decades, each study samples about 5.3 trials per decade. shows what goes wrong when the range is too narrow or too wide for one value's learning-rate curve.

A narrow range can miss the valley floor entirely. A new value of the scientific hyperparameter often moves the best learning rate, and a range centered on the old value can leave the new optimum outside. A wide range avoids that problem but spreads the trials thinly, so the trial nearest the floor may still be far from it. Both make a good option look worse than it is, and either can make the wrong option win.

How far above the floor a sparse study's best trial sits

If $K$ trials are spread roughly evenly over $W$ decades, the gap between neighboring trials is about $W/K$, and the trial nearest the best learning rate can be up to half of that away. Near its floor the curve is a parabola with curvature $c$, so the best trial can sit as much as

$$\Delta L_{\max} \approx c\left(\frac{W}{2K}\right)^{2}$$

above the floor. In the toy of , $c = 2.4$ per squared decade and $K = 16$. At $W = 1.375$ decades the bound is 0.004, and at $W = 5$ decades it is 0.059, ten times the 0.006 margin between the best option and the runner-up. The excess shrinks with the square of the density, so doubling the trials per decade cuts it by four.

repeats a whole design many times. The toy has three options for a scientific hyperparameter, each with its own learning-rate valley, and option 2 is truly best by a margin of six times the trial-to-trial noise. For each range width, the figure repeats the design 200 times and records how often it picks option 2.

With 48 trials and three options, the design never picks the right option below 1.2 decades, because option 2's best learning rate lies outside the range. It picks correctly 98% of the time at 1.375 decades and 52% of the time at 5 decades, as the trials thin out. A fourth option cuts each study to 12 trials, and the peak falls to 81%.

The peak width in the toy depends on knowing where every option's optimum lies, which you never know in a real round. The Playbook's practical answer is a generous range followed by a check. Plot the trials on an axis plot, and widen the range if the best ones sit near an edge (Part 5 covers these checks).

The same budget arithmetic applies to how many nuisance hyperparameters you tune. For Adam, the Playbook's FAQ gives a rule of thumb by study size (how to tune Adam ↗). Tune the learning rate alone below 10 trials, add $\beta_1$ between 10 and 25, add $\epsilon$ from 25 on, and add $\beta_2$ once you can run substantially more than 25. The authors are explicit that general statements about search spaces and trial counts are hard to make, so the ladder is a starting point.

In practice

Before launching a round, I find it helpful to answer six questions in order. They condense the Playbook's section on designing the next round of experiments ↗. The example column applies them to the depth comparison from Making a comparison fair.

1

What is the one question?

Write it as a comparison that one plot could settle.

ExampleDo six hidden layers give lower validation error than four?
2

Which hyperparameter answers it?

Mark it scientific. Keep its list of values short.

ExampleNumber of hidden layers, with values 4 and 6.
3

What could shift when it changes?

Mark them nuisance. Start with the learning rate and the other optimizer settings.

ExampleLearning rate and weight decay, searched separately for each depth.
4

What will you hold still?

Mark them fixed. Write down the caveat each one adds.

ExampleThe optimizer, dropout and ReLU stay as they are, so the answer holds for this optimizer and activation.
5

How will you spend the trials?

Divide the budget among the values, make the learning-rate range wide enough for every value, and tune no more nuisance hyperparameters than the trials per study support.

Example48 trials, 24 per depth, learning rate over 3 decades.
6

How will you score and check?

Score each trial by its best checkpoint on one evaluation schedule. Before reading the answer, check on axis plots that no best trial sits at an edge.

ExampleIf the six-layer study's best learning rate sits at the bottom of the range, extend the range downward and rerun.

The last step of the loop is deciding whether to adopt the change. The decision needs a sense of how much results vary from run to run, which Part 6 covers.
