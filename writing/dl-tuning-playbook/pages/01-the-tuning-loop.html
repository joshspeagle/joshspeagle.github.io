Part 1 of 9 · Experimental method and setup

Tuning a network one question at a time

Josh Speagle Notes on the Playbook's section on a scientific approach to improving model performance ↗

Part of a series of notes on Google Research's Deep Learning Tuning Playbook. Read what the Playbook is and how these notes work.

Suppose we have a network that trains and a validation score we would like to improve. The obvious next move is to change several things at once, or to hand every hyperparameter in the config to a search tool and launch a few dozen runs overnight. Either can lower the score, but neither tells us much about why, and that missing understanding makes every later decision harder. The Playbook argues instead for a slower loop in which each round of experiments asks a single question and is designed so that its answer can be trusted. In this first post I want to work through the pieces that make that loop function: how we score one training run, how we read a set of runs together, what it takes to compare two options fairly, and how a fixed budget of trials forces trade-offs among all three.

One question per round

Let's make this concrete. Validation accuracy has stalled a few points short of where we need it, and there is no shortage of ideas: switch optimizers, add dropout, add a learning-rate decay schedule, make the network deeper. If we try all four in one run and the score improves by half a percent, we have learned surprisingly little, because one change could account for the entire gain while another quietly made the model worse and slowed training down.

The opposite strategy is to put every hyperparameter into an automated search and let the algorithm sort things out. Godbole and colleagues consider this impractical because the space of configurations is so large; in their words, there are not yet "any algorithms sophisticated enough to efficiently search this space without human guidance." Even a coarse grid with three values for each of twelve hyperparameters has $3^{12} = 531{,}441$ points, so a search of 50 or 100 runs barely samples it.

What the Playbook proposes instead is an incremental tuning strategy (the Playbook's section ↗). We begin from a simple configuration that already works and improve it over a sequence of rounds, each of which asks one narrow question. Within a round we run a study, the Playbook's term for a set of training runs at different hyperparameter settings, and each run in the study is a trial. When the evidence says a change helps, we adopt it into our best configuration, and the Playbook calls that update a launch whether or not anything actually ships.

The Playbook's summary · The incremental tuning strategy ↗

Start with a simple configuration and incrementally make improvements while building up insight into the problem. Make sure that any improvement is based on strong evidence to avoid adding unnecessary complexity.

Each round cycles through the four steps in , and the first of them largely decides whether the other three can succeed. The Playbook asks for a goal narrow enough that a single round of experiments can make real progress on it. Its examples range from trying one potential improvement (a new regularizer, a preprocessing choice), to understanding the effect of a single hyperparameter such as the activation function, to greedily lowering validation error late in a project (choosing the goal ↗).

That last example hints at how rounds are distributed over a project. In practice, according to the Playbook, most of the time goes to gaining insight into the problem, which it calls exploration, and comparatively little to greedily lowering validation error, or exploitation (exploration vs exploitation ↗). This changes what counts as a successful round. A round in which a new regularizer fails to help is still useful if the plots show us why, because that insight carries forward: it tells us which hyperparameters the validation error is sensitive to, which ones interact and need to be re-tuned together, and which ones we can leave alone in future rounds. Only once the search space is well understood does a final stage switch to exploitation, which the Playbook suggests running with Bayesian optimization (Part 6).

Every step of the loop involves comparing training runs, so before anything else we need to decide which single number should stand for a run.

Scoring one training run

Say we train for 20,000 steps with some hyperparameter configuration $\mathbf{h}$, which bundles together the learning rate, the weight decay and every other setting of the run. To compare this run against others we have to reduce it to a single validation score, which the Playbook calls the trial's result. The natural default is the validation error at the final step, but there are two reasons why the end of training is often not where a run did best.

  • The run may have peaked earlier. A run with a high learning rate or little regularization can reach its best validation error partway through and then get worse as it starts to overfit the training set.
  • Validation measurements fluctuate. Even after the validation curve levels off, each evaluation still moves up and down a little from one checkpoint to the next, so a single reading at the last step can land on a high point purely by chance.

Both problems have the same remedy. The Playbook recommends running periodic evaluations at regular step intervals, keeping the few best checkpoints seen so far on disk (a small buffer), and choosing the best of them once the run ends (saving checkpoints ↗). In its terminology this is retrospective optimal checkpoint selection, and written out it defines the trial's result as the lowest validation error over the evaluation steps:

$$\hat{L}_{\text{trial}}(\mathbf{h}) \;=\; \min_{t \,\in\, \mathcal{T}_{\text{eval}}} L_{\text{val}}(\boldsymbol{\theta}_t).$$

Here $\boldsymbol{\theta}_t$ are the model's weights at step $t$, $L_{\text{val}}$ is the validation error, and $\mathcal{T}_{\text{eval}}$ is the set of steps at which we evaluate (every 1,000 steps in ). Because every trial runs to its full step budget and the checkpoint is chosen afterwards, we never need an early-stopping rule that has to guess, partway through training, when to quit. This is why the Playbook considers prospective early stopping usually unnecessary.

In the run has stopped improving by around step 5,000, so the whole 0.0090 gap between the last checkpoint and the best one is evaluation noise. On a run that overfits, the gap would also include the damage done by the later training steps.

Why the best checkpoint reads below the plateau

The toy's plateau is exactly 0.2, yet the selected checkpoint reads 0.1899. This is an order-statistics effect: taking the minimum of 20 noisy evaluations picks out the one with the largest downward fluctuation, so on average the minimum sits below the true plateau, and more evaluations give more chances for a low reading. Over 300 seeds of the toy, the median gap between the last and the selected checkpoint grows from 0.007 when we evaluate every 2,500 steps to 0.011 when we evaluate every 250 steps.

Here I'd go a step further than the Playbook, which doesn't discuss this bias. I think it has two practical consequences. Every trial we compare should be evaluated on the same schedule, so that no trial gets more chances at a low reading than another. And any number we report for the final model should come from a separate test set, because the selected checkpoint's validation error is biased low, a small instance of the winner's curse.

Each trial now gives us one number, but a round runs many trials, so the next question is how to read them together.

Reading a set of runs

Designing a study comes down to a few choices: which hyperparameters vary across trials, the range of values each may take (together, the search space), and how many trials to run. A search algorithm then chooses each trial's settings within that space (creating a set of studies ↗). shows a study of 20 trials that varies the learning rate $\eta$ and the weight decay $\lambda$ together. Each trial trains for 20,000 steps and reports its best checkpoint as above, and the trial with the lowest result is the study's best trial.

A table sorted by score would tell us which trial won, but not whether the search space was in the right place to begin with. For that question the Playbook recommends a basic hyperparameter axis plot, in which every trial's validation score is plotted against one hyperparameter, one point per trial (identifying bad search space boundaries ↗). The first thing to look for is where the best trials sit. If they crowd against one edge of the range, a better value may well lie beyond it, and the remedy is to widen the search in that direction and run again.

In the best trial sits comfortably inside the learning-rate range, which is what we hope to see. Switching panel (b) to weight decay gives a less tidy picture. The points spread up and down because each trial also had its own learning rate, so a trial with a good weight decay can still score badly if its learning rate was far off. On a projection like this, the informative feature is the lower edge of the cloud, which traces the best score reached at each weight decay.

That vertical spread is a hint of the next problem, because it shows that a hyperparameter we are not studying can still decide how good an option looks.

Making a comparison fair

Let's take a concrete round. Our model has four hidden layers, and we want to know whether six would reduce validation error. The quickest experiment keeps everything else from the current configuration, including the learning rate we tuned for four layers, changes the depth, and runs once.

The trouble is that the best learning rate generally depends on the architecture, so the value that suited four layers need not suit six. Running the six-layer model at the four-layer model's learning rate tests the new model at a setting tuned for the old one, and shows how that can mislead us.

The fix is to search the learning rate separately for each depth and compare the best result each depth reaches. The Playbook builds its whole approach to experimental design around this idea, giving every hyperparameter in a round one of three roles (identifying scientific, nuisance and fixed hyperparameters ↗):

  • Scientific hyperparameters are the ones whose effect we are trying to measure; in our example, the number of hidden layers.
  • Nuisance hyperparameters are the ones we tune separately for each value of the scientific hyperparameters so that the comparison is fair; here, the learning rate. We don't care about their values for their own sake, which is why the name borrows the statistical idea of a nuisance parameter.
  • Fixed hyperparameters keep a single value for the whole round. Fixing a hyperparameter saves trials but adds a caveat, because our conclusion may not hold at other values of it.

With these roles in place, we can say precisely what a round compares: the best score that each value of the scientific hyperparameter reaches once the nuisance hyperparameters have been tuned,

$$L^\star(h_{\text{sci}}) \;=\; \min_{\mathbf{h}_{\text{nuis}}} \, L(h_{\text{sci}},\, \mathbf{h}_{\text{nuis}}).$$

Here $h_{\text{sci}}$ is one value of the scientific hyperparameter (six layers, say), $\mathbf{h}_{\text{nuis}}$ collects the nuisance hyperparameters, $L$ is the validation error a run reaches, and the minimum runs over the nuisance search space. Godbole et al. describe this operation as "optimizing away" the nuisance hyperparameters. In practice we can only take the minimum over the trials we actually ran, so $L^\star$ is an estimate, and how good an estimate it is depends on how we spend those trials.

How much a fixed learning rate distorts the comparison

Suppose each option's validation error is a parabola in $x = \log_{10}\eta$ centered on its own best learning rate $x^\star(h_{\text{sci}})$, as in :

$$L(h_{\text{sci}}, x) = L^\star(h_{\text{sci}}) + c\,\big(x - x^\star(h_{\text{sci}})\big)^2.$$

At a fixed learning rate $x_0$, option A scores $L^\star(A) + c\,(x_0 - x^\star_A)^2$ and option B scores $L^\star(B) + c\,(x_0 - x^\star_B)^2$. The fixed comparison therefore charges each option a penalty that grows with the square of its distance from $x_0$. If we fix $x_0$ at the old model's best learning rate, the old model pays nothing while the new model pays $c\,(x^\star_A - x^\star_B)^2$. In the toy that penalty is $0.05 \times 0.8^2 = 0.032$, which is larger than the true advantage of $0.015$, and so the ranking reverses.

A statistician would recognize the curve $L^\star(h_{\text{sci}})$, a minimum over the nuisance parameters at each value of the parameter of interest, as a profile, the same construction that underlies the profile likelihood. The Playbook doesn't use the word, but its "optimizing away" is exactly this operation.

Which role does a hyperparameter take?

An important subtlety is that a role is not a property of the hyperparameter itself, since it changes with the goal of the round. The activation function, for instance, could be scientific in a round that compares ReLU and tanh, nuisance in a round that tunes it separately for each depth, and fixed in a round that tests something else on a ReLU network. Even so, some kinds of hyperparameters tend to fall into the same roles, and the Playbook offers rules of thumb for them:

  • Optimizer hyperparameters, such as the learning rate, momentum and Adam's $\beta$ parameters, are usually nuisance hyperparameters because they tend to interact most strongly with other changes. They are rarely scientific, since the best learning rate for today's pipeline may no longer be best after the next change to it. Fixing some of them is still acceptable when resources are short or when there is strong evidence that they don't interact with the question at hand.
  • The choice of optimizer is usually scientific when comparing optimizers is the question, and fixed otherwise.
  • Regularization splits in two. Whether to use a technique such as dropout is scientific or fixed, while the strength it introduces, such as the dropout rate, is a nuisance hyperparameter, and it remains one in later rounds once dropout has been adopted.
  • Architecture choices such as the number of layers are usually scientific or fixed because, as the Playbook notes, they tend to have large effects on training speed and memory use.

applies these rules to three goals, using the Playbook's own examples. Pick a goal and press a hyperparameter to read why it takes its role, or switch to "Test yourself" and try assigning the roles first.

The third goal in raises one more complication, because each optimizer brings its own settings: Nesterov momentum adds a momentum coefficient, while Adam adds $\beta_1$, $\beta_2$ and $\epsilon$. Hyperparameters like these, which exist only for some values of the scientific hyperparameters, are what the Playbook calls conditional hyperparameters. Both optimizers do have a learning rate, but the authors warn against treating the two as a single hyperparameter, because the ranges that work well for each typically differ by several orders of magnitude. Each optimizer's study therefore gets its own learning-rate search.

Every nuisance hyperparameter we tune consumes trials, however, and the number of trials in a round is set by the compute we have.

Spending a fixed budget of trials

How should a fixed number of trials be divided up? The authors frame this as a balance among three goals that any study design has to meet within a limited budget (striking a balance ↗):

  1. comparing enough different values of the scientific hyperparameters,
  2. tuning the nuisance hyperparameters over a large enough search space,
  3. sampling that search space densely enough.

Doing better on any one of them costs either more trials or some of another. To put numbers on the trade-off, suppose we can afford $K_{\text{total}} = 48$ trials and want to compare $M = 3$ values of a scientific hyperparameter, with one study per value. Each study then gets $K$ trials, spread over a learning-rate range $W$ decades wide (a decade is a factor of 10, so the range from $10^{-4}$ to $10^{-1}$ spans three decades), and the density of trials per decade is

$$K = \frac{K_{\text{total}}}{M}, \qquad \rho = \frac{K}{W}.$$

With 16 trials over 3 decades, each study samples about 5.3 trials per decade. Whether that is enough depends on how the range lines up with each option's learning-rate valley, and sketches what goes wrong when the range is too narrow or too wide for one value's curve.

The two failure modes pull in opposite directions. A narrow range can miss the valley floor entirely, which is a real risk because a new value of the scientific hyperparameter often moves the best learning rate, and a range centered on the old value can leave the new optimum outside. A wide range avoids that problem but spreads the trials thinly, so the trial nearest the floor may still be far from it. Either way a good option looks worse than it is, and when that happens to the best option, the wrong one can win.

How far above the floor a sparse study's best trial sits

If $K$ trials are spread roughly evenly over $W$ decades, neighboring trials are about $W/K$ apart, so the trial nearest the best learning rate can be up to half of that away. Near its floor the curve is a parabola with curvature $c$, which means the best trial can sit as much as

$$\Delta L_{\max} \approx c\left(\frac{W}{2K}\right)^{2}$$

above the floor. In the toy of , $c = 2.4$ per squared decade and $K = 16$. At $W = 1.375$ decades the bound is 0.004, while at $W = 5$ decades it is 0.059, ten times the 0.006 margin between the best option and the runner-up. Because the excess shrinks with the square of the density, doubling the trials per decade cuts it by a factor of four.

To see how often these failures actually change the answer, repeats a whole design many times. The toy has three options for a scientific hyperparameter, each with its own learning-rate valley, and option 2 is truly best by a margin of six times the trial-to-trial noise. For each range width, the figure reruns the design 200 times and records how often it picks option 2.

With 48 trials and three options, the design never picks the right option below 1.2 decades, because option 2's best learning rate lies outside the range. It picks correctly 98% of the time at 1.375 decades, but only 52% of the time at 5 decades, where the trials have thinned out. Adding a fourth option cuts each study to 12 trials and lowers the peak to 81%.

Of course, the toy's ideal width depends on knowing where every option's optimum lies, which we never know in a real round. The Playbook's practical answer is to start with a generous range and then check it: plot the trials on an axis plot, and widen the range if the best ones sit near an edge (Part 5 covers these checks).

The same budget arithmetic governs how many nuisance hyperparameters we can afford to tune. For Adam, the Playbook's FAQ offers a rule of thumb keyed to study size (how to tune Adam ↗): tune the learning rate alone below 10 trials, add $\beta_1$ between 10 and 25, add $\epsilon$ from 25 on, and add $\beta_2$ once you can run substantially more than 25. The authors are explicit that general statements about search spaces and trial counts are hard to make, so I'd treat this ladder as a starting point rather than a rule.

In practice

Pulling these threads together, I find it helpful to answer six questions, in order, before launching a round. They condense the Playbook's section on designing the next round of experiments ↗, and the example column applies them to the depth comparison from Making a comparison fair.

1

What is the one question?

Write it as a comparison that one plot could settle.

ExampleDo six hidden layers give lower validation error than four?
2

Which hyperparameter answers it?

Mark it scientific. Keep its list of values short.

ExampleNumber of hidden layers, with values 4 and 6.
3

What could shift when it changes?

Mark them nuisance. Start with the learning rate and the other optimizer settings.

ExampleLearning rate and weight decay, searched separately for each depth.
4

What will you hold still?

Mark them fixed. Write down the caveat each one adds.

ExampleThe optimizer, dropout and ReLU stay as they are, so the answer holds for this optimizer and activation.
5

How will you spend the trials?

Divide the budget among the values, make the learning-rate range wide enough for every value, and tune no more nuisance hyperparameters than the trials per study support.

Example48 trials, 24 per depth, learning rate over 3 decades.
6

How will you score and check?

Score each trial by its best checkpoint on one evaluation schedule. Before reading the answer, check on axis plots that no best trial sits at an edge.

ExampleIf the six-layer study's best learning rate sits at the bottom of the range, extend the range downward and rerun.

That leaves the last step of the loop, deciding whether to adopt the change. Making that decision well requires a sense of how much results vary from run to run, which is the subject of Part 6.
